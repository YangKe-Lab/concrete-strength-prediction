# 案例画布解析（从 .pgz 卡组文件中读出）

本文档是把 `cases/*/case/*.pgz` 卡组文件解开后**逐卡解析**得到的卡片清单、参数值与连线关系，
用于核对画布、复现接线、或在没有 E-GAMA 的机器上了解卡组内部结构。

## 1. .pgz 是什么（以及怎么离线解析）

`.pgz` 不是 zip，而是 **单条 raw-deflate 流**，解压后是一份 UTF-8 带 BOM 的 XML（根元素
`<PGW_FILE ver="v05" gver="5.1.1.424">`），由 `<AllCardsOnDeck>` 下的 `<Card>` 元素描述每张卡：

```python
import zlib
xml = zlib.decompressobj(-15).decompress(open("抗压强度预测.pgz", "rb").read())   # wbits=-15 = raw deflate
```

每个 `<Card>` 内：

| 元素 | 含义 |
|---|---|
| `TPN` / `ASN` | 卡片类型全名（如 `MyGamaCards.TrainModelCard`）与所在程序集 |
| `<CardInsG>` | **卡片实例 GUID**——连线指向的就是它 |
| `<CardLt>` | 卡片在画布上的位置与尺寸（`RectangleF`） |
| `<PCDMngr><Ins>` | 输入端口列表，每个端口是一个 `<DataCard>`（端口自身 GUID 即 `CardGuid`） |
| `<PCDMngr><Outs>` | 输出端口列表 |
| `<DFTDAT><im>` / `<DCDataList><base64Binary>` | 端口当前值（.NET BinaryFormatter 序列化后 base64） |
| `<DCBSrc><SourceGuid>` | **该端口连到哪张卡**（上游卡片实例 GUID） |
| `<CBFields>` | 显示信息：`CardName` 端口全名 / `CardNS` 端口短名（卡片表面显示的就是它）/ `CardDesc` 说明 |
| `<KVP><Key>_userText</Key>` | 文字白板卡里用户输入的文本 |

> ⚠️ **读卡组时的坑**：端口自带的 `DFTDAT` 只是**缓存显示值**，端口真正取值可能来自连线的
> 文字白板卡或滑动条卡（例如线性模型卡的「模型类型」端口缓存写着 `interaction`，实际值来自它连到
> 的文字白板）。只看 `DFTDAT` 会误判参数——必须同时看 `DCBSrc`。
>
> 字符串值的 blob 结构：17 字节头（`0001000000ffffffff0100000000000000`）+ `0x06` + objId(4) +
> 7bit 变长长度 + UTF-8 字节 + `0x0b`；数值则是 `SystemClassWithMembersAndTypes` 的 `m_value` 成员
> （Int32=ptype 8 / Double=6 / Bool=1）。现成工具：`tools/pgz_tool.py`（`dump` / `paths` / `rewrite`）。

## 2. 卡片清单（两套卡组完全同构）

| 卡片类型 | 张数 | 作用 |
|---|---|---|
| `InputDataCard` 输入数据 | **10** | 5 个模型 × (训练集 + 测试集) |
| `DenseLayerCard` 全连接层 | **5** | ANN① Dense(10)+Dense(1)；ANN② Dense(5)+Dense(5)+Dense(1) |
| `ActivationCard` 激活函数 | **3** | ANN① 1 个；ANN② 2 个（均 `leaky_relu`） |
| `TrainModelCard` 训练模型 | **2** | ANN Model1 / ANN Model2 |
| `LinearModelCard` 线性模型 | **3** | `simple` / `interaction` / `poly` |
| `CompareCard` 结果对比 | **1** | 汇总 5 份模型报告 → 5 页对比图 |
| `DecimalSliderCard` 数字滑动条 | 9 | 隐含层/输出层单元数、迭代轮数、学习率的**值来源** |
| `TextStreamCard` 文字白板 | 14 | 数据路径、激活类型、线性模型类型、模型名称、对比标题（**值来源**） |
| `CardGroupCard` 卡片组 | 5 | 把每个模型的卡打包成组，便于拖拽 |
| **合计** | **52** | 其中顶层处理器卡 21 张 + 参数/标签卡与分组 |

## 3. 参数值（两套卡组一致，直接读自卡组）

| 参数 | 值 | 来源 |
|---|---|---|
| 迭代轮数 epochs | `10000` | 训练模型卡（另有滑动条可调） |
| 学习率 lr | `0.0001` | 训练模型卡 |
| 随机种子 seed | `42` | 训练模型卡 |
| 批大小 | `32` | 输入数据卡（**当前版本不生效**，本项目为全批量梯度下降） |
| 验证集比例 | `0.2` | 输入数据卡（**当前版本不生效**） |
| 包含表头 / 分隔符 | `True` / `,` | 输入数据卡 |
| 特征列 / 标签列 | 留空 = 除最后一列外为特征、最后一列为标签 | 输入数据卡 |
| 激活类型 | `leaky_relu` | 激活函数卡（值来自文字白板） |
| 线性模型类型 | `simple` / `interaction` / `poly` | 线性模型卡（值来自文字白板） |
| ANN 模型名称 | `ANN Model1` / `ANN Model2` | 训练模型卡（值来自文字白板，作图例） |
| 线性模型名称 | `线性模型1` / `线性模型2` / `线性模型3` | 线性模型卡 |
| 对比标题（案例一） | `混凝土抗压强度预测` | 结果对比卡 |
| 对比标题（案例二） | `鸢尾花分类案例` | 结果对比卡 |

## 4. 连线关系（卡级）

**数据线**——10 张输入数据卡的「数据路径」端口全部连到 2 张**文字白板**：

```
文字白板('…\train.csv')  → 5 张「训练集」输入数据卡.数据路径     （每个模型一张）
文字白板('…\test.csv')   → 5 张「测试集」输入数据卡.数据路径
```

**层链**（串联接法，共 6 根 1 对 1 的线，见 `连线方案.md` §2.5）：

```
ANN 3-10-1 ：全连接层(10).模型 → 激活函数.上游模型 ; 激活函数.模型 → 全连接层(1).上游模型
ANN 3-5-5-1：全连接层(5).模型 → 激活①.上游模型 → 全连接层(5).上游模型 → 激活②.上游模型 → 全连接层(1).上游模型
```

**训练线**：

```
每张训练模型卡：模型 ← 层链末端.模型 ； 数据集 ← 对应「训练集」输入数据卡 ； 测试集 ← 对应「测试集」输入数据卡
               迭代轮数 / 学习率 ← 滑动条卡 ； 模型名称 ← 文字白板
```

**线性模型线**：

```
每张线性模型卡：训练数据集 ← 「训练集」输入数据卡 ； 测试集 ← 「测试集」输入数据卡
               模型类型 ← 文字白板（simple / interaction / poly） ； 模型名称 ← 文字白板
```

**汇总线**（结果对比卡，用的是**一模型一口**的最稳接法）：

```
模型报告1 ← ANN Model1.模型报告      模型报告2 ← ANN Model2.模型报告
模型报告3 ← 线性·简单.模型报告       模型报告4 ← 线性·交互.模型报告
模型报告5 ← 线性·多项式.模型报告     对比标题  ← 文字白板
```

## 5. 仓库内卡组文件的两处改动（脱敏）

原始 `.pgz` 里数据路径是本机绝对路径（含 Windows 用户名），不适合进公开仓库，因此仓库内的两份
`.pgz` 做了**改写后重新压缩**，其余字节与结构完全未变（改动行已逐行核对 diff）：

| 卡组 | 改动 | 效果 |
|---|---|---|
| `cases/01-concrete-strength-prediction/case/抗压强度预测.pgz` | 路径文字白板清空 + 关联的测试集输入卡「内置数据集」设为 `test` | 开箱即用：加载卡片内置的同一份 66/16 混凝土 demo 数据 |
| `cases/02-iris-classification/case/鸢尾花案例.pgz` | 路径改为相对路径 `data\iris_train.csv` / `data\iris_test.csv` | 若平台不解析相对路径，按该案例 README 改成绝对路径即可 |

其余内容（卡片位置、连线、参数、标题、滑动条刻度）与原始卡组逐字节一致。
